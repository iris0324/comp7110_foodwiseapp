## 快照与事务

数据库 `FoodWise-Prototype3-v1`，当前 schemaVersion=1。`app` 的固定 `snapshot` key 包含 settings、foodItems、foodEvents、receiptImports、cart、drafts、purchases、purchaseItems、stories、storyActions、outcomes 和 appliedOperations；`media` 按 imageId 保存小票 Blob。

每次 `Store.commit()` 建立稳定操作身份、expectedRevision、epoch、issuedAt、type 与 payload。`Repository.commitCommand()` 在同一 readwrite 事务内重新读取快照并调用 `executeCommand()`：

1. schema 不支持时拒绝，绝不静默清库；当前没有旧 schema 需要迁移。
2. epoch 不符时拒绝旧回调。已存在 operationId 必须内容一致，直接返回原结果，不被旧 revision 阻断。
3. 新操作必须符合最新 revision，再运行纯 reducer 与不变量。领域错误不进入保存重试队列。
4. Blob 与快照一起写入。只有事务 complete 后更新已提交快照、反馈成功和执行导航。
5. abort 保留原快照、输入和原命令；重试复用 operationId。相关按钮锁定，仍有领域身份校验。

多标签页只防止旧覆盖，未提供协作。冲突时保留编辑，提示读取最新已存数据；用户再提交。重置使用新 epoch、同事务清 media 并恢复样例。正常动画计时从不修改快照。

## 数据含义

真实库存与 Ghost 表完全独立；标记实际买到也不会创建实物。食物“更新余量”设置剩余值，大于当前数量须资料更正；零余量须确认用完。丢弃、用完、误录删除保留不同事件，结果退出可用列表。类别、搜索、日期排序组合工作，未知日期后置；所录日期到达不自动改状态。

Ghost 的 cartItemId、purchaseItemId、storyId、actionId 和 purchaseId 各自稳定。名称只用于同名比较，允许 trim／大小写规范化，不合并批次、不推断同义词。结账保留原名称、数量、条目估价和备注；当前估价写 outcomes，历史不改写旧收据。

数量输入最多 6 位小数、最大 1,000,000；购买数量故事的本轮使用量最多 7 位小数，支持最小合法数量的一半。统一 BigInt 以 10^8 为尺度计算并存规范十进制字符串；无浮点残余或静默截断。金额严格解析为整数分，空=null，零=0；最大 AUD 9,999,999.99。日期是 YYYY-MM-DD，1900–2200 年真实日历日；时间事件为 ISO 时间戳，界面按语言和本地时区显示。

`Estimated Unspent = sum(contribution(outcome,item))`：not_bought 计原总价；bought_less 按 actualReductionQuantity / 原数量计比例金额，BigInt 计算后四舍五入到分；bought / unconfirmed 为零。reductionQuantity 保存计划减少量，与 actualReductionQuantity 独立。未知价不累计，零价有效；估价／实际数量变更自动重算，不按故事模拟用量计价。

## 故事和动作

状态 source → 问题 → action_ready → action_result → 下一个相关问题／recap → intention → completed。播放阶段属于临时展示态。默认用量选择覆盖 36 条路径（9／9／18），最长 2／2／3 问；用户主动部分分享后的额外处理不属于这 36 条默认路径，允许继续处理剩余。仅有剩余才问处理；分享、收好、未打开、不确定可结束，不预设浪费。

回答提交后保存待执行 actionId 和用量。有效拖拽、下方按钮或气泡键盘入口调用同一 `action_apply`。持久化成功后才播放，连续咀嚼不重复扣量。已执行恢复静止结果，未执行恢复等待，继续也须提交。分享从 remainingQuantity 扣除并累计到 sharedQuantity；usedQuantity 只计享用。分享／享用可在 action_ready 修改数量，与 action_apply 同一事务保存；部分分享后继续 leftover_question。收好不扣量。原数量＝已享用＋已分享＋剩余。

默认享用 4700 ms：650 接收、750 入口、2000 享用、700 吞咽、600 满足。用已有透明四帧配合位移与嘴形变化；饮品使用饮用姿态。收好 1900、分享／时间 2000、风险 2300、不确定 1200、继续收好 1500 ms。减少动态效果时简化至 250 ms，结果与手动继续相同。图形在动作结尾更新，数字是依据。

动画绑定 epoch、itemId 和 actionId。退出、切商品、语言切换、修正与重置取消计时。无效落点及 pointercancel 只复位；仅可拖动气泡设置 touch-action:none，页面可正常滚动。

自定义文字逐商品／storyRevision 保存，模板必须手动选。无模板的用量、余量和 recap 都是 null，先文字确认再意向，完成成功前仍进行中。进行中修正须确认，从当前模板首问重做；更换来源回 source，原购买／现实结果不变。完成后 UI 和命令都禁止重演。

## 草稿、错误及内容安全

receipt 编辑保存 rawRows／imageId 到 receiptImports 的 draft，cart 保存原始行和草稿，custom 按商品／版本保存字段。允许不完整字段。统一守卫记住一次目标，保存成功再去、放弃回到上次保存、继续保持编辑。刷新只尽力触发平台 beforeunload，不能保证未存恢复。

图片先检查类型、10 MB 和可解码性，成功才替换旧预览。object URL 退出／换图释放；Blob 随明确保存落盘。异步预览有请求标记、编辑对象与 epoch 校验。模拟生成失败保留内容、可重试。初始化错误显示重试，不回退到“只在内存里保存”。

用户输入通过 `esc()` 或 textContent 插入，不当 HTML 执行。长原文、标签、引号和换行已实测。表单 label 与 aria-label 对应；校验标记错误字段并聚焦。原生 dialog 管理焦点和 Esc，保存失败的重试按钮放在当前模态框内。发布源模块统一带 `?v=6.3`，避免开发时缓存的新入口引用旧依赖。

## v6.3 兼容与界面

沿用原 v1 IndexedDB 数据库，无清库。Repository.load 与命令执行在内存中补齐 sharedQuantity：旧记录按已执行分享动作累计，重算余量与回顾；下一次正常提交保存更新。重试重放也返回兼容后的快照，升级不会重复扣除。金额新字段为增量字段，旧三种实际结果继续支持。

食物详情 available 状态使用同页表单，quantity 对应初始量，remaining 对应余量；零余量确认携带全部编辑字段；历史状态不显示编辑表单。unit 空字符串合法；日期状态类统一由 dateClass 计算。非大精灵页面在 sticky 页头显示小精灵。模块与 CSS 缓存版本统一为 v6.3。
