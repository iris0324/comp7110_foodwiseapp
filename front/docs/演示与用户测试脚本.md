# 演示与用户测试脚本

2026-10-22。用于功能演示和后续用户测试。本轮没有招募或研究结果。先按 README 启动固定来源，说明所有小票生成／扫描／购买／故事均为模拟，真实库存来自用户明确录入。

## 开始前

1. 使用非隐私浏览器打开 127.0.0.1:7116；若需要干净演示，设置→重置→确认，得到四条食物和空车／空历史，语言保持所选。
2. 准备一张普通测试图片，确认不含需要对外展示的私人信息。图片只留在本地；演示也可直接用示例小票。
3. 向观察者说明：精灵会按选择扮演用户。意向、实际结果和库存分别记录；“估算未支出”不等于已核实储蓄。

## A：购后整理到使用

1. 首页→食物管理→添加食物→上传小票。实际选图并查看预览，再点击“生成演示清单”。询问是否理解生成行不是 OCR 结果。
2. 删除一行、改一行名称和数量、补一行遗漏。至少一条日期留空。先保存草稿离开，再回来查看图片与文字。
3. 明确“确认加入我的食物”。检查新批次；用搜索＋类别找到同名不同批次，数量／日期各自独立。
4. 详情设置今天计划，调整、取消；更新余量为原量的一部分。用完另一条，丢弃第三条，误录删除另一次测试录入。从历史结果核对三种处理。
5. 刷新。确认已保存食物／计划／事件恢复，未知日期仍未知，日期已过仍不会自动丢弃。

观察：录入字段是否负担过重？“所录日期”是否被误解为系统保证安全的期限？用户是否理解余量是剩下多少？是否能区分用完与丢弃？

## B：虚拟体验到逐项完成

1. 添加三个任意商品，示例 Chocolate 数量2、总价3.50，Oat milk数量1、估价空，Other snack数量3.5、估价0.00。选择对应示意图；演示模拟扫描和可忽略同名参考。
2. 虚拟结账一次。核对收据三个条目、3.50已填合计、1个未知价；没有支付。单件测试时不应出现商品切换。
3. 第一件选食用量、一半；先拖到无效处，再拖到精灵身体。观察接收、入口、咀嚼、吞咽与满足停顿。一次动作应该用1、剩1，手动继续。
4. 剩余选分享；看短动作和三段回顾，分享1未变成再吃1。下一步任选三种意向或清空，然后“完成本件”。
5. 第二件选购买数量，输入全部数量，使用点击或 Enter／Space 等效享用；全部应跳过剩余问题。完成后回看，不应出现重演按钮。
6. 第三件写自己的原文，手动选 time 模板体验；另开一条选“没有适用模板”，确认只保存文字、未模拟，经过可选意向再完成。

观察：用户是否理解精灵扮演自己？拖拽接收区是否清楚？4.7秒是否过长或过短？结果和“继续”是否足够清楚？保留剩余是否被误认为尚未完成？自定义模板选择是否需要更多解释？

## C：中断、草稿和现实结果

1. 小票／购物车／自定义各写未保存内容，然后切模块。各试继续编辑、保存后离开、恢复后修改再放弃。新内容无旧草稿也试一次放弃。
2. 多件故事自由切换：A确认用量但未执行→切B写自定义草稿→回A。A仍等待；执行后在动画中切B／刷新，再回A直接静止结果。点击继续后刷新恢复下一问。
3. 输入中切语言；动画中切语言。用户原文不翻译，状态与当前商品不能串用。
4. 已有一个3.50和一个未知估价条目：都未确认时0；第一条标“本次未买”变3.50；第二条标未买但未知价仍3.50；补4.00变7.50；第一条改实际买到变4.00；第二条改未确认撤回至0。检查旧收据仍是结账时估价。
5. 进行中修正：先取消，保持原步骤；再确认，从首问重做。实际结果不变。完成后只回看，但可改结果／估价／意向。
6. 在设置取消一次重置，确认数据仍在；再确认重置，刷新得到4条样例和空历史，语言保持。

观察：保存与确认是否混淆？金额是否仍被理解为真实付款／省钱？用户是否能找到实际结果？完成故事和吃完是否被混为一谈？中断恢复是否符合预期？

## 开发者失败演示

仅使用测试数据，进入 tests/failure.html。先在框架内编辑商品，点击框架外“一次写入失败”控件，再保存草稿后离开。应显示失败与弹层内重试，不能离开或丢字段；重试应使用同一 operationId，成功只去原目标一次。

`?story=<purchaseItemId>` 可验证动作自动保存失败；`?receipt=1` 可注入一次清单生成失败。正常产品入口没有这些控制。损坏 PNG、非图片和大于10MB图片用于校验，已有预览和字段应保留。纯逻辑测试和原生指针操作的边界见验收记录。

记录参与者原话、完成路径、停顿、误解和需要帮助的位置。不要预设用户应选择不买，不将购买评价为失败，不编造测试人数或效果。
